# @oge-ui/react-charts

> React charts on a dependency-free SVG kernel: sixteen cartesian series types (line/spline/step/area/stacked/bar/range/scatter/bubble/candlestick), pie and doughnut, radar/polar and a range selector — time and log axes, multiple value axes, strip lines, annotations, wheel/drag zoom and pan, crosshair, shared tooltips, an interactive legend, selection, keyboard point inspection and PNG/SVG export — running the same charts engine and stylesheet as the Angular charts package.

Part of OGE UI v1.1.1.
Docs and live demos: https://www.ogeui.com/components/charts
Whole-suite reference: https://www.ogeui.com/llms-full.txt

```sh
npm i @oge-ui/react-charts
```

## Writing OGE React code

Follow these rules and generated code compiles on the first try.

1. **These are plain React components.** Import the component and render it:
   `import { OgeButton } from '@oge-ui/react-buttons'`. There is no module, no
   provider requirement and no `imports` array — that is the Angular package.
2. **Import the stylesheet once, at your app entry.**
   `import '@oge-ui/react-buttons/styles.css'`. Components ship no inline
   styles; without this import they render unstyled.
3. **Props are plain props, not signals.** Write `text="Save"`,
   `severity="accent"`, `disabled`. Never call them (`text()`), and never use
   `[prop]`/`[(prop)]` binding syntax — that is Angular template syntax.
4. **Modes are string unions, never enums.** Write the literal:
   `severity="danger"`, `stylingMode="outlined"`, `size="sm"`,
   `selectionMode="single"`. There is no `OgeButtonSeverity.Danger`.
5. **Events are `on*` callbacks taking the payload directly** —
   `onClick={(event) => …}`, `onActionDone={(result) => …}`,
   `onSelectionChange={(change) => …}`. Note this is the mirror image of the
   Angular naming rule: there, outputs drop the `on` prefix; here React's
   convention wins, and the payload is the argument rather than an event object.
6. **Two-way state is the controlled/uncontrolled pair.** Pass `selectedKeys`
   plus `onSelectionChange` to control it yourself, or `defaultSelectedKeys`
   to let the component own it. Same for the button's `loading` /
   `onLoadingChange`.
7. **App-wide defaults and every user-facing string** come from a context
   provider: `<OgeButtonsConfigProvider config={{ clickGuardMs: 300,
   messages: { loading: 'Yükleniyor' } }}>`. That is how localization works;
   there is no i18n dependency. Per-instance overrides use the `messages` prop.
8. **Styling is CSS custom properties**, all prefixed `--oge-`, identical to
   the Angular packages — the two render layers share one stylesheet. Never
   target internal class names; override the token.
9. **Slots are props that take nodes**, not children with directives:
   `icon={<SaveIcon />}`. Free `children` render inside the button after the
   label.
10. **Server components:** every component is a client component
    (`'use client'` is already in the package). Import them from a client
    component, or mark your own file `'use client'`.

### Theming

```css
:root {
  --oge-accent: #4f46e5;   /* selection, focus, primary actions */
  --oge-radius-lg: 10px;
}
```

The theme stylesheets are shared with the Angular packages and ship in
`@oge-ui/core` (installed with every package; add it directly under pnpm):
`@oge-ui/core/themes/dark.css` (then `class="oge-theme-dark"` or
`data-oge-theme="dark"` on `<html>` or any subtree; `"auto"` follows
`prefers-color-scheme`), plus the `tailwind.css` and `bootstrap.css`
bridges.

## Common mistakes

Predictable wrong guesses, and what to write instead.

| Wrong | Right |
| --- | --- |
| `import { OgeButton } from '@oge-ui/buttons'` | `from '@oge-ui/react-buttons'` — the unprefixed package is Angular |
| `imports: [OgeButton]` | nothing — just render `<OgeButton />` |
| `[text]="label"` / `[(loading)]="busy"` | `text={label}` / `loading={busy} onLoadingChange={setBusy}` |
| `(clicked)="save()"` | `onClick={save}` |
| `onClick={(e) => e.cancel = true}` | there is no cancelable pre-event on the React buttons |
| `severity={OgeButtonSeverity.Danger}` | `severity="danger"` |
| forgetting the stylesheet | `import '@oge-ui/react-buttons/styles.css'` once at the app entry |
| `<OgeButton icon="save" />` | `icon={<SaveIcon />}` — slots take nodes |
| `::part` / overriding `.oge-button-native` | override a `--oge-*` token |
| rendering it from a server component | mark the file `'use client'` |

## API reference

### <OgeChart>

#### Properties

_Data & series_

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `dataSource` | `readonly T[]` | `[]` | Data items; never mutated. |
| `series` | `readonly OgeChartSeriesInput[]` | `[]` | Series definitions: `type` (26 kinds — see `OgeChartSeriesType`), field mapping (`valueField`/`argumentField` — names, dotted paths or getters), `name`, `color`, `axis` (value-axis index), `stack` group, `dashStyle`/`width`/`opacity`, `showInLegend`, rangeArea bounds (`value1Field`/`value2Field`) and candlestick/ohlc OHLC (`openField`/`highField`/`lowField`/`closeField`), `sizeField` (bubble area), `visible` (start hidden; the legend re-shows) and `showLabels` (shorthand for `label.visible`). The per-point, label and analytics options are listed under _Series options_. Null/NaN values render as gaps. Inline arrays are fine: structurally equal props never rebuild the chart. |
| `commonSeries` | `Partial<OgeChartSeriesInput>` | `{}` | Defaults merged under every series (dx `commonSeriesSettings` parity). |
| `palette` | `readonly string[] \| undefined` | `—` | Series colors; defaults to the 10-color `OGE_CHART_PALETTE` (concrete hex values so exported images keep their colors). |

_Series options (OgeChartSeriesInput)_

| Name | Type | Description |
| --- | --- | --- |
| `label` | `OgeChartLabelOptions` | Data labels on any cartesian or polar series: `{ visible?, position?, format?, showForZero?, overlap? }`. `position`: `'outside'` (default; past the bar end / above the point), `'inside'`/`'insideEnd'`, `'center'`, `'insideBase'` — inside labels pick a contrasting text colour from the mark. `format(info)` returns the text (`info.text` is the SI default, `info.percent` the full-stacked/pareto share). `overlap`: `'hide'` (default) drops a label that would cover an earlier one, `'shift'` nudges it clear first, `'none'` keeps all; labels are always pulled inside the plot. Labels never change the screen-reader data table. |
| `colorField / customizePoint` | `field \| (info: OgeChartPointInfo) => OgeChartPointStyle` | Per-point colour from the data, or a hook returning `{ color?, label?: { visible?, text? }, marker?: { visible?, size? }, description? }` per point (wins over `colorField`). Bars, markers, candles, OHLC ticks, boxes and polar sectors take the colour; the legend swatch stripes the distinct colours; the tooltip marker follows the point. `description` is spoken in the tooltip, the announcement and the sr-table cell — colour is never the only channel. |
| `trendline` | `OgeTrendlineType \| OgeChartTrendlineOptions` | A regression or smoothing line over the series: `'linear' \| 'exponential' \| 'logarithmic' \| 'polynomial' \| 'movingAverage'`, or `{ type, order? (polynomial 2–6), period? (moving average), color?, width?, dashStyle? ('dash'), showR2? }`. `showR2` appends the trend value and R² to the series' tooltip row. The fit is the pure `ogeTrendline()`. |
| `indicator` | `OgeChartIndicatorOptions` | For `type: 'indicator'`: `{ type: 'sma' \| 'ema' \| 'bollinger' \| 'macd' \| 'rsi', period?, stdDev?, fastPeriod?, slowPeriod?, signalPeriod?, levels? }` computed from `valueField` (or `closeField` of OHLC data). Bollinger draws a band and two lines, MACD a signal line and a histogram, RSI reference levels at 30/70. Default names like `SMA (10)` come from `messages.values`. Put RSI/MACD on a second value axis (`axis: 1`) — separate panes are a future addition. |
| `summaryField / upColor / downColor / totalColor / showConnectors` | `field / string / string / string / boolean` | `waterfall`: values are deltas floating from the running total; `summaryField` marks sums — `'total'` (or `true`) spans zero → running total, `'intermediate'` the subtotal since the previous intermediate sum. Rising/falling/sum bars colour `upColor` (green), `downColor` (red), `totalColor` (the series colour); dashed connectors join the bars (`showConnectors: false` drops them). The sr table and tooltip say _increase_/_decrease_/_total_. |
| `valuesField / q1Field / medianField / q3Field / outliersField / whiskers` | `field / … / 'tukey' \| 'minMax'` | `boxPlot`: from raw values (`valuesField` holding a `number[]` per category — quartiles by linear interpolation, Tukey 1.5 × IQR whiskers by default, the rest as outlier dots) or precomputed (`lowField`/`q1Field`/`medianField`/`q3Field`/`highField`, `outliersField`). The tooltip and sr table read _Min, Q1, Median, Q3, Max_. Pure: `ogeBoxStats()`. |
| `bins` | `OgeHistogramBinning` | `histogram`: bins `valueField` over the whole data source — `{ count? }` (default: Sturges' rule, rounded to a 1-2-5 width), `{ width? }` or explicit `{ thresholds? }` edges. Bars span their bins on a linear argument axis; the argument reads `start – end`. Pure: `ogeHistogramBins()`. |
| `cumulativeAxis / cumulativeColor` | `number / string` | `pareto`: categories sort by value (descending) and a cumulative-% line with dots runs over the bars. `cumulativeAxis` puts the line on a declared value axis (give it `position: 'end'`; it spans 0–100); without one the line uses an implicit 0–100% scale. The tooltip adds _cumulative 45%_. |

_Axes_

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `argumentAxis` | `OgeChartAxisOptions` | `{}` | Argument axis: `type` auto-detects (numbers / dates / categories) when unset; `min`/`max`, `inverted`, `grid`, `title`, `labelFormat`, `labelOverlap` (`rotate`/`skip`/`none`). |
| `valueAxis` | `OgeChartAxisOptions \| readonly OgeChartAxisOptions[]` | `{}` | One or more value axes; series pick theirs via `axis`. `position: 'end'` renders on the right, `type: 'logarithmic'` spaces decades evenly, `abbreviate: false` disables SI labels (`1.2K`). |
| `stripLines` | `readonly OgeChartStripLine[]` | `[]` | Argument-axis markers: `{ start, end?, label?, color? }` — a line without `end`, a shaded band with it. |
| `annotations` | `readonly OgeChartAnnotation[]` | `[]` | Plot annotations: `type: 'point'` draws a marker dot with a connector into a label box at (`argument`, `value`); `'text'` places the label alone (top of the plot without a value). `axis`, `color` and `offsetX/Y` refine placement. |

_Interaction_

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `zoomEnabled / panEnabled` | `'none' \| 'wheel' \| 'drag' \| 'both' / boolean` | `'none' / false` | Cursor-centered wheel zoom (a non-passive listener, so the page does not scroll under it), drag-select zoom (Escape cancels mid-drag, 8px threshold), Shift+drag pan. Escape on the focused plot resets the zoom. |
| `visualRange / defaultVisualRange` | `OgeChartRange \| null` | `undefined / null` | The zoom window in argument-axis units (`null` = full extent) — controlled when `visualRange` is provided (pair it with `onVisualRangeChange`), otherwise seeded by `defaultVisualRange`. Writes clamp into the data bounds. |
| `tooltip` | `OgeChartTooltipOptions` | `{}` | `{ enabled?, shared? }` — shared lists every series at the hovered argument; otherwise the value-nearest series wins. |
| `crosshair` | `OgeChartCrosshairOptions` | `{}` | `{ enabled?, horizontal? }` — the vertical tracker snaps to the nearest argument (binary search). |
| `legend` | `OgeChartLegendOptions` | `{}` | `{ visible?, position? (top/bottom/start/end), interactive? }` — real buttons with `aria-pressed`; clicking toggles the series and the axes rescale. |
| `selectionMode / selectedPoints / defaultSelectedPoints` | `'point' \| 'series' \| 'none' / readonly OgeChartPointRef[]` | `'none' / undefined / []` | Click (or Enter) selects; Ctrl adds points to the set; series mode selects the whole series. `selectedPoints` is controlled when provided (pair it with `onSelectedPointsChange`). |

_Export entry points (lazy)_

| Name | Type | Description |
| --- | --- | --- |
| `exportChartToPng / exportChartToJpeg / exportChartToSvg / serializeChartSvg / rasterizeChartSvg` | `@oge-ui/react-charts/export-image` | No third-party libraries: the live SVG is cloned with computed styles inlined, then downloaded as a standalone `.svg`, or rasterized onto a canvas (`pixelRatio`, `background`) for `.png` or `.jpeg` (`quality`, default 0.92 — JPEG has no alpha, so the background fills first). `rasterizeChartSvg(svg, options)` returns that canvas for custom pipelines. | `exportChartToPdf / buildChartPdfDocument / chartPdfLayout` | `@oge-ui/react-charts/export-pdf` | A one-page PDF: the chart rasterized like the PNG export and embedded into a jsPDF page (`orientation` from the aspect, `pageFormat` `a4`, `margin` 12 mm) under an optional `title`/`subtitle` drawn as real PDF text with `font` — or the font registered via `setOgePdfDefaultFont()` from `@oge-ui/behavior` (Turkish, Greek, Cyrillic need a Unicode font). `jspdf` is an optional peer pulled in only by this entry; `buildChartPdfDocument` returns the `jsPDF` document, `chartPdfLayout` the pure page geometry. |

_Analytics (pure functions)_

| Name | Type | Description |
| --- | --- | --- |
| `ogeSma / ogeEma / ogeBollingerBands / ogeMacd / ogeRsi` | `(values, period, …) => aligned arrays` | The technical indicators the `indicator` series runs, for your own pipelines: `ogeSma(values, period)`, `ogeEma(values, period)` (seeded with the first SMA), `ogeBollingerBands(values, period = 20, stdDev = 2)` → `{ middle, upper, lower }[]`, `ogeMacd(values, 12, 26, 9)` → `{ macd, signal, histogram }[]`, `ogeRsi(values, 14)` (Wilder). Input: numbers or `{ value }` objects; output aligned with the input, `null` until the window fills. |
| `ogeTrendline` | `(points, type, options?) => OgeTrendlineFit \| null` | Least-squares fits over `{ x, y }` points: `'linear'`, `'exponential'` (y > 0), `'logarithmic'` (x > 0), `'polynomial'` (`order` 2–6, x normalized so epoch-ms arguments stay well-conditioned) and `'movingAverage'` (`period`). Returns `{ coefficients, r2, predict(x), points }`. |
| `ogeBoxStats / ogeHistogramBins` | `(values, …) => OgeBoxStats \| OgeHistogramBin[]` | `ogeBoxStats(values, 'tukey' \| 'minMax')` → `{ low, q1, median, q3, high, mean, outliers }`; `ogeHistogramBins(values, { count?, width?, thresholds? })` → `{ start, end, count, indexes }[]` (the last edge inclusive). |

| `value / defaultValue` | `OgeChartRange \| null` | `undefined / null` | The selected window in argument units (`null` = full range) — controlled when provided. Share one state between it and a chart's `visualRange` and the two stay in lockstep. |
| `scaleType` | `'time' \| 'linear' \| undefined` | `—` | Auto-detects from the first argument (dates → time) when unset. |
| `palette / locale / messages` | `see OgeChart` | `—` | Shared options; handle labels come from `messages.aria.rangeStart/rangeEnd/rangeWindow`. |
| `className / style` | `string / CSSProperties` | `—` | Applied to the `.oge-range-selector` host. |

#### Methods

_OgeRangeSelectorHandle (ref)_

| Name | Type | Description |
| --- | --- | --- |
| `reset()` | `void` | Back to the full range (`onValueChange(null)`). |

#### Events

| Name | Type | Description |
| --- | --- | --- |
| `onValueChange` | `(value: OgeChartRange \| null) => void` | The controlled half of `value`. Interaction: drag the window (grab cursor), drag either handle, click the track to center the window there — Escape mid-drag restores; the handles are WAI-ARIA sliders (arrow keys adjust by 2%, Home/End jump to the bounds, changes announced). |

### Configuration

#### Properties

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `OgeChartsConfigProvider` | `component ({ config?: OgeChartsConfigInput })` | `—` | Configures every chart below the provider — the React counterpart of `provideOgeChartsConfig()`. Shallow merge over the outer provider (or `OGE_DEFAULT_CHARTS_CONFIG`) per top-level key — a partial `messages` replaces whole nested blocks — and it re-resolves whenever `config` changes, which is how the UI language switches at runtime. |
| `useOgeChartsConfig()` | `OgeChartsConfig` | `—` | The resolved config of the current subtree. |
| `messages` | `OgeChartsMessages` | `—` | Every user-facing string, aria labels included: `aria` (`OgeChartsAriaMessages` — chart/pie labels with `{title}`/`{count}`, table caption, plot hint, legend label), `announcements` (`OgeChartsAnnouncementMessages` — live-region templates with `{series}`/`{argument}`/`{value}`), `values` (`OgeChartsValueMessages` — the words of analytic value texts: box-plot `low`/`q1`/`median`/`q3`/`high`/`outliers`, waterfall `increase`/`decrease`/`intermediate`/`total`, pareto `cumulative`, `upper`/`lower`/`signal`/`histogram`, the trendline suffix `trend` with `{value}`/`{r2}`, the histogram `bin` and the default indicator names `sma`/`ema`/`bollinger`/`macd`/`rsi`) and `noData`. Defaults: `OGE_DEFAULT_CHARTS_MESSAGES`. |
| `locale` | `string \| undefined` | `—` | BCP 47 locale for every `Intl` format in scope; a per-instance `locale` prop wins. |
| `a11yTableLimit` | `number` | `50` | Rows of the screen-reader data table. |
| `markerThreshold` | `number` | `200` | Marker circles render only up to this many points per series — beyond it the single path carries the series alone. Line-family paths additionally auto-downsample with LTTB to about one point per pixel once a series outgrows the plot width (hit-testing and tooltips keep the full data). |

```ts
  const [range, setRange] = useState<OgeChartRange | null>(null);
  return (
    // 50,000 points per series stay fluid: paths auto-downsample with LTTB
    // (Largest-Triangle-Three-Buckets — peaks survive) to roughly one point per
    // pixel, hit-testing is a binary search over the FULL data and pointer work
    // is rAF-coalesced. Wheel zooms around the cursor, dragging selects a
```
