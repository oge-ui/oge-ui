# Competitive gap research — navigation / layout / overlay / tabs / buttons / BPMN

Date: 2026-10-03. Read-only research; no repo changes, no builds.

**Method.** I took OGE's surface from `apps/dev-app/src/app/pages/{navigation,layout,overlay,tabs,buttons,bpmn}/*-api-data.ts`, cross-checked it against the React twins (`pages/react-*`, `packages/react/*/src/lib`), read the per-component parity tables in `ROADMAP.md` (lines 314-478 and 700-1884) and grepped `packages/` source to confirm every "Missing".

The competitor feature lists come from my knowledge of the official docs: DevExtreme 25.x, Kendo UI for Angular 2025-26, Syncfusion Angular 2025-26 and bpmn-js / Camunda Modeler. They were **not** fetched live in this session. Where I am unsure a competitor ships something, the row says _Unverified_.

Legend: **dx** = DevExtreme, **K** = Kendo UI for Angular, **S** = Syncfusion Angular, **P** = PrimeNG (context only).
Impact and Effort are each H/M/L (high/medium/low) for Impact and S/M/L (small/medium/large) for Effort.

**React parity.** Every family in scope has a React twin: `react/layout`, `react/navigation` (tree-view, drawer, stepper, menubar, breadcrumb, pagination), `react/overlay` (menu-list, popup, tooltip, context-menu, modal plus modal-provider, toast, live-announcer), `react/tabs`, `react/buttons` and `react/bpmn`. Each gap below therefore applies to **both** layers, so closing it costs twice (Angular plus React, plus the parity gate).

---

## 1. Headline finding

The **existing** components are unusually complete. Every one has a ROADMAP parity table against dx/Kendo/Prime/Material, and most rows say Done. Several OGE extras go beyond the references: async guards, cancelable pre-events, `compactBelow` container adaptivity, toast `promise()` and coalescing, tab dirty dots and async close guards, hold-to-confirm and autoRepeat buttons, and BPMN keyboard connect plus live narration.

**The real gap is breadth, not depth.** Paid suites ship 15-25 navigation, layout and feedback widgets that OGE lacks entirely. The most important are Popover, ListView, Chip/ChipList, Avatar/Badge, Timeline, TileLayout/Dashboard, Carousel/ScrollView, ActionSheet, FAB/SpeedDial, Sortable/Draggable utilities, confirm/alert dialog helpers, a non-modal Window, a LoadPanel, Chat/AI Prompt, and Diagram, FileManager, PDF viewer and Spreadsheet.

## 4. Top 15 gaps for this family (prioritized)

The order weighs impact × competitor coverage ÷ effort, and favors gaps that reuse primitives OGE already has.

1. **Popover**: a component and directive on `OgeAnchoredPanel` + `oge-popup`, with title/body/actions, arrow, show-on click/hover/focus and focus management. (H, S; 3/3 competitors)
2. **Confirm / alert / prompt helpers** on `OgeModalService` and React modal-provider: `confirm({title, message, severity:'danger'}) → Promise<boolean>`, plus localized messages. (H, S; 3/3)
3. **Chip / ChipList**, with selection modes, removable chips and avatar/icon. Reuses the tag-box chip internals. (H, S; K/S/P/Material)
4. **ListView**: templated, virtualized, grouped, selectable, infinite/paged, searchable, with optional reorder. Reuses the select-list core and virtualizer. (H, M; 3/3)
5. **BPMN linting / problems panel**, with a bpmnlint-like rule set, `validate()` API and offender overlays (the Overlays API already exists). (H, M)
6. **BPMN extensibility**: a pluggable properties panel (templates/providers), custom palette and context-pad entries, documentation and event-definition payload fields. (H, M)
7. **TileLayout / Dashboard** with drag, resize, reorder and persistable layout. Pairs with charts, grid and card. (H, M-L; 3/3)
8. **Chat + AI Prompt** as one conversational-UI package: message list, typing indicator, attachments, suggested actions, prompt box with output cards. (H, M; 3/3)
9. **Tooltip rich content and arrow**: `TemplateRef` / React node content, a callout arrow shared with popover, and `showOn`. (M, S)
10. **ContextMenu programmatic `open(x,y)`, selector delegation and cancelable `opening`** for per-target dynamic items. (M, S; 3/3)
11. **Avatar + standalone Badge + inline Message/Alert**, shipped as a small "indicators" batch. (M, S each)
12. **FAB / SpeedDial + standalone toggle button** (`[(pressed)]`), shipped as a buttons batch. (M, S-M)
13. **LoadPanel + circular determinate progress**, shipped as a feedback batch. (M, S)
14. **Non-modal Window** (modeless, multiple, z-order on focus, minimize), as a mode of the modal. (M, M; 3/3)
15. **Timeline + Carousel/ScrollView + ActionSheet**, shipped as a "content and mobile" batch. (M, S-M)

Next tier: generic Diagram (built on bpmn-engine), PanelBar (nested accordion), cross-tree drag and drop, mega menu / "More" overflow in menubar, drawer `items` list and swipe gestures, Camunda/Zeebe property editing, DMN, FileManager, PDF viewer, Spreadsheet and Ribbon.

## 5. Entirely missing components ranked by competitor coverage

- **3 of 3 (dx/K/S):** ListView, Popover, confirm/alert dialog helpers, FAB/SpeedDial, Carousel/ScrollView/Gallery, TileLayout/Dashboard, Sortable/Draggable, Chat, Diagram (Kendo's is Unverified), non-modal Window, RichTextEditor (adjacent), Map (adjacent), LoadPanel (Kendo's container form is Unverified).
- **2 of 3:** Chip/ChipList, Avatar, Badge, Timeline, ActionSheet, AppBar, circular progress, AI Prompt/AssistView, FileManager, PDF Viewer, Spreadsheet, QR/Barcode, Smart Paste, Stack/Grid layout, PanelBar.
- **1 of 3:** inline Message, BottomNavigation, Ribbon, Image Editor, MultiView, Resizable.
- **0 of 3 (differentiators):** Tour/guided steps, notification center.

**Cost note.** Every new component must ship in both render layers and pass the four doc gates: api-data, snippets, `llms`, and parity in `check-parity.mjs`. The S/M/L efforts above exclude that overhead, which is roughly +40-60% per item.
